## 📝 Notiz 3 — STONE-Preis 7,11× bei Spielstart ohne Lager

**Beobachtung:** STONE-Preis bei 7,11× Anker in den ersten Minuten, bevor überhaupt ein Lagerhaus/Werkstatt existiert.

**Root Cause:** `FlowPrices.effectiveCoverage()`:
- `stock=0`, `supplyPerDay=0`, `demandPerDay>0` (Vanilla-Bauaufträge)
- Coverage → 0.0 → `scarcityMultiplier` ≈ 69× (gedämpft durch `phaseFactor` → ~7–37×)
- D-001 deckt nur `RESOURCES.EDI()` — **STONE, _WOOD, METAL etc. haben keinen Cap**

**Fundstelle:** `FlowPrices.java:108-115`, `EconomySim.java:869` (`flowDefaultTargetCoverageDays=1.0`)

**Mögliche Fixes:**
1. Cold-Start-Guard in `effectiveCoverage()`: wenn `supplyPerDay=0` UND `stock=0` → coverage=1.0
2. `flowPricingEnabled` erst aktivieren wenn erstes Lagerhaus/Werkstatt existiert
3. `phaseFactorMin` senken oder `phaseFactorThreshold` erhöhen

### 🔴 KRITISCH: `emigrationRisk` ist DEAD CODE

`EconomySim.emigrationRisk` (AtomicInteger) wird:
- **inkrementiert** in `updateDemography()` bei `hunger>=90`
- **genullt** einmal pro Spiel-Tag
- **NIRGENDWO GELESEN** — kein Getter, kein Consumer, keine Engine-Kopplung

Die echte Emigration läuft via `Wallets.emigrating[]` ← `STATS.POP().EMMIGRATING` (Vanilla-Engine).

**Konsequenz:** Der gesamte D-002-Fix (0.0001→0.00003 + `roster.size()>=20` Guard) verändert einen Counter mit null Effekt auf das Spielverhalten.

## 📝 Notiz 5 — Einwanderung zu langsam + 50% arbeitslos bei Spielstart

**Beobachtung:** Immigration dauert ewig, ~50% der Bürger arbeiten zu Beginn nicht.

**Immigration-Analyse:**
- `MeticImmigration`: Booster auf `BOOSTABLES.CIVICS().IMMIGRATION` → bei Tax=0 neutral (1.0×)
- `hungerImmigrationEnabled=true` + `hungerImmigrationStrength=0.5` → dämpft Immigration bei Nahrungsknappheit
- Spielstart: kein Farm-Output → Hunger-Signal aktiv → Immigration zusätzlich gebremst

**Arbeitslosigkeit-Analyse:**
- `LaborMarket.update()`: nur alle `laborRefreshDays=50/300≈0.17d` (~50 Ticks)
- `minimumWorkersPerWorkplace=1` — Firmen starten mit 1 Arbeiter
- `firmSizingHillclimbStep=1` — Firmen wachsen um max 1/Tick
- `laborFrictionPoints=2` — Reibung im Arbeitsmarkt
- `OddjobMarket`: Surplus-Laborer → Tagelöhner, aber `oddjobWagePerTask=3` (sehr niedrig)
- Spielstart: 20 Bürger aber nur 2–3 Workplaces → strukturelle Arbeitslosigkeit

**Mögliche Ansätze:**
1. `laborRefreshDays` senken (50→20 Ticks) für schnellere Arbeitnehmer-Vermittlung
2. `minimumWorkersPerWorkplace` erhöhen (1→2) für schnellere Firmen-Belegung
3. `oddjobWagePerTask` erhöhen (3→10) damit Tagelöhner attraktiver werden
4. `hungerImmigrationStrength` senken (0.5→0.2) für weniger Hunger→Immigration-Bremse am Start

## 📝 Notiz 6 — Produktion beginnt erst nach erstem Lagerbau

**Beobachtung:** Erst nachdem das erste Stockpile/Lager gebaut wurde, beginnt die erste Arbeitergruppe effektiv zu produzieren.

**Analyse:** Vanilla-Engine-Verhalten — Produktionsgebäude benötigen ein Stockpile als Output-Ziel. Ohne Lager können Arbeiter nichts produzieren, weil die Engine keinen Zielort für Output-Ressourcen hat. Sobald das erste Stockpile existiert, beginnt die Produktion. Kein Mod-Bug — vanilla game mechanic.

**Interaktion mit Notiz 3 (STONE-Preis):** Sobald das Lager existiert und Produktion startet, ändert sich `supplyPerDay` von 0 auf >0. FlowPrices `effectiveCoverage()` wechselt vom Zero-Demand-Pfad (bei demand=0) zum Supply-Tracking-Pfad mit D-004-Inflow-Check. Der STONE-Preis sollte sich normalisieren sobald Produktion läuft.

## 📝 Notiz 7 — Korrigierte Diagnose: FlowMeter-Blindspot (Jagen/Sammeln)

**Wichtige Korrektur zur CSV-Diagnostik-Analyse:**

Die ursprüngliche Analyse ("Farm produziert NULL → Root Cause") war **unvollständig**, weil zwei fundamentale Fakten nicht berücksichtigt wurden:

1. **Getreide braucht ein volles Jahr:** Saat im Frühling → Ernte erst im Spätsommer. Dass FARM_GRAIN in den ersten ~90 Tagen null Output zeigt, ist Vanilla-Spielmechanik, kein Bug. Die CSV beginnt bei Tag 188 — das ist mitten im zweiten Jahr, aber:

2. **Jagen und Sammeln sind für FlowMeter unsichtbar:**
   - Bürger können jagen (Wild) → Nahrung geht DIREKT an den Bürger, nicht durchs Lager
   - Spiel startet mit initialer Nahrung (nicht im Stockpile)
   - `FlowMeter.stockOf()` zählt NUR `SETT.ROOMS().STOCKPILE.tally()` + Eateries/Canteens
   - **→ `supplyPerDay=0` im FlowMeter bedeutet NICHT, dass Bürger hungern!**

**Konsequenz für die Diagnostik:**
- `food_days=0` in der Macro-CSV: kein Essen IM LAGER, aber Bürger können via Jagd satt sein
- `food_basket_price=737`: Mod reagiert auf selbst-geschaffene Phantom-Knappheit
- Der "Geld-Drucker" (treasury → wallets) könnte ein Phantom-Problem sein, das NUR entsteht weil der Mod Jagen/Sammeln nicht sieht

**Design-Gap:** `FlowMeter` braucht einen Weg, nicht-Stockpile-Nahrungsquellen zu erkennen:
- `FACTIONS.player().res().in(FResources.RTYPE.PRODUCED)` trackt Engine-weit alle Produktion
- `RESOURCES.EDI()` listet alle essbaren Ressourcen
- Ein `producerlessProduced`-Zähler existiert bereits in `FlowMeter` für nicht-Industry-Output
